## Part 1 — Foundations

### 1.0 Foundation rules (F-IDs)

| ID | Rule |
|---|---|
| **F-01** | **Never crop a Game Card.** Every surface renders the full face, scaled — never cropped, never slivered. (OQ-014; ties to CARD-07) |
| **F-02** | **The step diagonal belongs to the card.** The TL+BR pixel-step is the GameCard's signature; all other chrome is square 90°. A button may borrow the step at **half scale (2/4)**, and **colour disambiguates intent** (OQ-036): **gold + step = an _acquisitive_ action** — creating a card (ADD), **moving PIXELS** (the currency mark, `PriceChip`, `BuyBar`/CLAIM — gold is the economy's colour, ECON-01), or a **primary add-to-collection / queue** (ratified 2026-06-23) · **system-orange + step = a prominent _non-acquisitive_ action** (RETRY, ADD FRIEND, SHARE). Step + a card's own colour = a GameCard; step + gold = get / make / spend; step + orange = borrows the geometry, not the identity. Gold stays **off** secondary or incidental controls (SHARE · RETRY · nav · a generic CTA). *(The avatar "design" affordance is a circular corner badge — no step — and is exempt.)* |
| **F-03** | **Keycap physics on the shell; flat + Scanline Energize on screen.** The shell's 5 nav keys stay tactile keycaps — a hard `0 4px 0` drop edge that travels down when pressed. **On-screen** action buttons + tool keycaps are **flat 2D** (no raised edge, no press-travel); **pressed/active = Scanline Energize** — fine CRT scanlines over a hairline-darkened fill, no motion (`motion.scanlineEnergize`). The C5 square chrome + the F-02 corner-step stay. *(OQ-006 → Keycap take 2026-06-11; the on-screen `0 3px 0`/`0 2px 0` raised edge + press-travel **deprecated** → flat / Scanline, owner-locked 2026-06-18.)* |
| **F-04** | **Nav legibility beats customization.** Shell colours/stickers may never obscure the 5 nav keycaps or their labels. (DEV-01) |
| **F-05** | **Pips: shell LEDs are lights, on-screen pips are pixels.** The shell's indicator LEDs — the `NavBand` active pip and the power LED — are **round** lit pips (physical lights, not panels). **On-screen position pips** (CardFan / carousel swipe dots) are **square, pixel-stepped, flat** — the `StateMark` notch geometry (`scr.accent` lit / `scr.grip` off, 6px, no glow), on-screen chrome per F-07. *(On-screen status/notification dots — `er-dot`/`kb-dot` — stay round lit pending owner; owner squared the position pips 2026-06-26.)* |
| **F-06** | **The 4-step type scale is law on screen** (21/15/11/9). **The card nameplate is a UI label, not print — F-06-bound: a plate must render ≥ 9px; card sizes too small to hold it drop the plate and name the game beside/below** (decision 0047, reverses the prior print-exempt carve-out). The card *back* stat print still scales with the card. |
| **F-07** | **Radius lives on plastic.** Rounded corners exist only on the physical shell (device, bezel, keycaps). On-screen chrome is square (C5). |
| **F-08** | **One font per surface.** Chakra Petch is THE screen font (every text on the app screen, incl. card plates, buttons, tags, links); Paytone One is THE plastic font (silkscreened shell labels). No third voice. |
| **F-09** | **No sunken containers.** Panels, wells, tiles, rows, and selection states never render inset/"carved-in" — surfaces are flat planes one step lighter than their background; **selection = an accent border (+ the `StateMark`)**, never an inset shadow or a darkened recess. The on-screen selection marker is the **orange pixel-square** (`scr.accent`, flat, square, one-pixel-notched corners — `StateMark`), **not** the pink LED pip. *Exceptions by name:* **shell nav keycaps** (they physically travel — F-03's shell metaphor) and **text inputs** (the cream inset field). *(On-screen pressed buttons no longer travel or sink — they **Scanline Energize**, flat; 2026-06-18.)* **Selection borders + the `StateMark` use the screen accent (`scr.accent`), not `brand.accent`** (owner pass-5 — pink stays the **SHELL LED** voice only, F-05; it is no longer the on-screen selection marker). (Owner rulings: "flat panels — not something Game Boy had," 2026-06-10; the report-drawer selection, 2026-06-12; the on-screen marker audit, 2026-06-15.) |

### 1.2 Typography (`type.*`)
- **Families (F-08):** `type.ui` = Chakra Petch — the screen font (all on-screen text incl. card plates, buttons, tags, links) · `type.shell` = Paytone One — the plastic font (shell labels only). *Silkscreen retired in v0.3.*
- **Scale (screen, F-06):** `type.display` 21px · `type.emphasis` 15px · `type.body` 11px · `type.micro` 9px. Weights 600–700; micro labels letterspaced 1–2px, uppercase.
- **F-06 is law — the mockups CONFORM, F-06 is NOT amended (owner ruling, decision 0024 / OQ-066):** the 2026-06-16 DS-conformance audit found the `*-states.html` boards consistently drifting **off-scale** (state-titles 17px shared across ~7 screens · some titles 13px · dense body/sub 10–10.5px · "mini" action buttons 9px, Settings SEND 12px). The ruling is to **snap each off-scale value to the nearest of 21/15/11/9** — no new `state-title`/`mini-button` role is carved out. *Off-scale → snapped:* 17 → **15** (emphasis) · 13 → **15** · 12/10.5/10 → **11** (body) · stray 9px buttons → the button tier's 11px. **The actual ~7-board conformance SWEEP is a separate follow-up task — flagged owed below, NOT done in this pass** (no board edited here).
- **Card nameplate (F-06-bound, decision 0047):** plate = `type.ui` 700, **≥ 9px** (≈10px @ hero/grid/`/cell`); **`/mini` + `/thumb` carry no plate** — the title is named beside/below (row title or caption). The card *back* stat print still scales with the card.
- **Plate legibility floor (owner pass-2, add-game track):** in **interactive fan/picker contexts** plates render **≥10px forefront / ≥9px neighbors** — the plate band grows to fit (two-line wrap allowed); deep-mini contexts (shelf strips, deal thumbs) stay exempt — the surrounding meta carries identity there. *Editor ripple: start-from templates keep a minimum plate-band ratio so baked plates (CARD-01/15) stay legible at fan sizes.*

### 1.3 Spacing, corners, elevation
- **Spacing scale:** 2 · 4 · 6 · 8 · 12 · 16 (+18 panel padding). Grid gutter 12; Top-3 gutter 9 · Top-10 view 2-up gutter 12; screen gutter 12–16.
- **Corner system (C5):** on-screen chrome square. GameCard step (TL+BR): 4/8 double-step @ hero/grid · 3 single @ cell/mini · 2.5 @ thumb; art and plate repeat the diagonal at smaller steps. ADD exception = 2/4 (F-02). Shell radii: device 30 · bezel 20 · keycap 15 · screen 13 · mini-device 7. **Step grammar (decision 0041, OQ-085):** the step is **intrinsic per component** — GameCard (+art/plate/ghost/skeleton/error placeholders) · `StateMark`/pips · **intent-buttons only** (gold+step = acquisitive · orange+step = prominent non-acquisitive); **everything else on-screen is square — there is no board-level `.c5` chip gate** (any square-chrome reset is its own rule). `.seal` (report) + `.cel-badge` (achievements) are **square**.
- **Elevation:** shell = soft physical (inset highlights + `0 4px 0` ink edges). Screen keycaps = **flat** — `shadow.key` (the `0 3px 0`/`0 2px 0` raised edge + inset bevel + the clipped `drop-shadow`) is **deprecated** for on-screen (2026-06-18); pressed/active = `motion.scanlineEnergize`, not a raised edge. `shadow.card` `0 4px 7px rgba(0,0,0,.35)` drop · `glow.pip` `0 0 6–9px` accent.

### 1.6 States & feedback (the §1.8 pattern, visual side)
Every screen's load/empty/error cells resolve to one family (OQ-037; behavior in design-req §1.8). All share the **dashed stepped-card silhouette** so they read as kin, split by intent:
- **Retryable** — `LoadError` "Signal Lost" (network/timeout/5xx): accent **!** + orange `ScreenButton/action-alt` **RETRY**.
- **Terminal** — `Unavailable`: muted grey person-glyph, **no retry**, GO BACK. MOD-09 non-disclosure — blocked/suspended/deleted all collapse here, indistinguishable. **Lone exception:** your *own* block shows **Unblock**.
- **Offline** — `Offline`/`OfflineStrip` (SYS-10): calm wifi-off glyph, **auto-recovers**, never an alarm; your own data stays read-only-usable, writes gated.
- **Loading** — `Skeleton`: **solid** fills (not dashes), so loading never reads as an invitation.
- **Empty** — `EmptyState/inviting`: a doorway, never a dead end (design-req §1.7).
- **Transient** failures (save/publish/purchase) → `Toast`: a **full-bleed banner sliding under the header** — what failed + a plain-words reassurance ("nothing was charged — your pixels are safe") + orange `ScreenButton/action-alt` RETRY where safe to repeat. *(Designed on the Store board; reusable verbatim by every transient write.)*
- **State-title type (F-06 conformance, decision 0024 / OQ-066):** the error/empty **state-titles** (today drawn at the off-scale 17px across ~7 boards) snap to **emphasis 15** — centered small-card titles read as 15, not display 21. Conform on the sweep (below); F-06 is not amended.

### 1.7 Inputs & keyboard (OQ-035)
Text entry uses the **system keyboard** — `keyboardAppearance` matched to the active `scr` theme (dark themes → dark keyboard), the focused field **riding just above** it. The nav band may be occluded while typing; that's accepted (typing is a focused sub-task; dismissing the keyboard returns to it). This keeps autocorrect / swipe / dictation / i18n / screen-reader support — the "stay conventional in forms" half of the art-direction split (design-req §1.1). A device-skinned **in-app keycap keyboard** (maximum metaphor) was considered and **deferred** for its autocorrect/swipe/dictation loss + i18n/a11y cost. Goes live with **Add Game**, the first heavy text surface. Field components themselves are §1.5 gaps.
