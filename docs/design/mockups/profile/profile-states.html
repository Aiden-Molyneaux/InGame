Edit, fresh, loading, error, offline and friend-view are all transforms of this — same skeleton, different fill or chrome.

Edit mode (in-place — identity + curation only)

The EDIT keycap presses + lights and the screen edits in place (the OQ-034 doctrine; tap again to exit) — per-field commit, no giant save. Editable: avatar → opens the card-style editor via a corner ✎ badge (PROF-08) · username w/ cooldown microcopy + screening (PROF-06 — the §1.8 inline-validation showcase) · bio w/ counter · genres from the controlled list (CAT-04, drawer-chip reuse) · gamertags ✕/add (PROF-02) · pinned favourite + Top-5 swap & re-rank (SOC-04; the OQ-031 ARRANGE gesture, reused).

Deliberately not editable here: Now Playing (set from Collection, WTP-03), Device (Device editor), stats (derived), privacy (Settings, PROF-03) — each dimmed row says where it does live, so edit mode teaches the information architecture instead of hiding it.

Fresh account (every empty names its action)

The inviting-empties doctrine (§1.7) applied to identity: dashed ghosts for bio, gamertags, pick and Top-5 — same silhouette language as the Collection's first-add ghost, each one a tappable nudge, never a scold. The default monogram avatar is the PROF-08 guarantee — you exist before you've designed anything.

Friend view (default — your chrome stays)

Your device is your constant frame (decision 0012): Riko's profile renders inside your teal shell + Midnight screen; their device appears as an on-screen hero with the explicit VIEW IN THEIRS toggle. The head shows whose profile (RIKO + FRIEND tag); identity adds friend count + mutuals; an explicit VIEW COLLECTION plus the Top-3 cards / VIEW TOP 10 are the doors into their collection (COL-10, read-only — decision 0050). A Top-3 card tap opens their Collection in TOP view, focused on that game.

Tools swap for the social job (PROF-05/SOC-02): VIEW COLLECTION (the primary door) + COMPARE (SOC-03), with Report / Block in the ⋯ overflow (MOD-01, SOC-09) — present but not foregrounded. No EDIT, no Settings: management chrome belongs to the owner.

Privacy-limited (the non-friend surface)

PROF-03's limited public card: avatar, username, member-since and mutual-friend count (the trust signal) — nothing else leaks. The lock-well borrows the inviting-empty bones: it names what unlocks and offers the one action (ADD FRIEND), an invitation rather than a wall.

Corner-colour rule (owner): ADD FRIEND wears the pixel-step in system orange, not gold — gold + step is reserved for card-creating actions (the Collection's ADD-game), so a stepped button that isn't card-related takes orange and never falsely reads as "makes a card."

Safety stays reachable: Report / Block live in the ⋯ overflow even at this visibility level (MOD-01, SOC-09) — you never need to befriend someone to report them.

Loading (skeleton — the silhouettes hold the layout)

Solid quiet fills in the exact silhouettes of the loaded screen — section headers stay, card shapes keep their stepped corners, nothing shifts when data lands. No spinners. Dashed = invitation, solid = loading: the two ghost languages never share a costume, so a skeleton can't be misread as an empty state.

Tools sit dimmed until data lands. (OQ-015 idea: the shell's power LED could pulse while loading — the device "thinking.") Offline is not this state and not an error: SYS-10 keeps your own shelf readable from cache.

Load-error (named state, always a retry)

The §1.8 load-error family: same bones as the inviting empties (stepped card silhouette, eyebrow, one loud action) but the dashed card carries a ! and the action is RETRY — recovery, not invitation — RETRY is orange + step (a non-card action, the corner-colour rule). GO BACK is the quiet second exit.

Boundaries: this state is for load failures only — action failures get a toast/banner + retry in place; offline is not an error (SYS-10): your own profile renders from cache, and this screen appears only when a fetch genuinely fails.

Profile unavailable (the terminal state — one mask, many causes)

The non-retryable twin of "Signal Lost." Blocked (either direction), suspended (MOD-09) and deleted (AUTH-07) accounts all land here, deliberately identical — the app never reveals which, nor who blocked whom (the non-disclosure rule). No identity, no stats, no RETRY (retry can't fix a permanent condition); GO BACK is the in-content exit, and the nav band still works.

Muted by design: the dashed card holds a quiet person-glyph in grip-grey, not the accent ! of an error — this reads as absence, not failure, so it's never mistaken for a retryable Signal Lost.

… except your own block (the lone disclosed case)

The one terminal case that names itself. When you are the blocker you already hold the knowledge, so this variant is explicit — it shows the handle and offers UNBLOCK (calm cream, not a loud invite; unblocking is a considered act, not a celebration). Report stays in the ⋯ overflow.

Same shell as the generic state — the only deltas are the named title and the Unblock action. That minimal difference is the safety argument made visible: strip those two and "you blocked them" becomes "they blocked you" becomes "deleted," all indistinguishable.

Offline — your profile (SYS-10: opens usefully)

No blank screen, no error. Your last-synced profile renders from cache, read-only, under a lightweight offline strip (muted, with a last-synced stamp — calm, not alarm). The whole thing stays browsable; only writes are gated — EDIT & SHARE sit dimmed (they need connectivity), Settings stays reachable.

The strip is the reusable offline indicator (same on Collection, etc.). The power LED could echo it (OQ-015). This is the SYS-10 promise made visible: a bad connection never costs you your own shelf.

Offline — a friend you can't reach (calm, not Signal Lost)

The friend case I flagged. A friend's profile needs a live, privacy-gated fetch — offline with nothing cached, you can't show it. But offline ≠ error (SYS-10): same wifi-off glyph in grip-grey (not the accent !), "YOU'RE OFFLINE" not "couldn't load," and no loud RETRY — it loads itself on reconnect. The sub points you to what does work (your own shelf), so it's never a dead end.

Three calm-vs-alarm cousins, now distinct: Signal Lost (accent !, orange RETRY — transient fetch failure) · Unavailable (person glyph, GO BACK only — permanent) · Offline (wifi-off, auto-recovers — transient connectivity). A recently-viewed friend may instead render read-only from cache like the self view — the exact cache scope is a SYS-10 detail (OQ-037).
