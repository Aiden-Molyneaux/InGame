Report Sheet Drafts — one pattern, every report surface · 3 models × 2 targets (C5 v2)

`ReportSheet` — the reusable report pop-up for everywhere reports happen: published cards, catalog entries, and users (MOD-01). Three genuinely different interaction models — /drawer (the OptionSheet family, refined) · /modal (the conventional centered dialog — §1.1's legible pole) · /takeover (a brief FlowHeader flow, one decision per zone) — each shown carrying both target shapes: a catalog entry (DUPLICATE · INCORRECT INFO; the latter selected with its required details note revealed) and a user (ABUSIVE PROFILE · IMPERSONATION · SPAM + the BLOCK offer in the same flow, SOC-09). The v0.11 rulings are baked in everywhere: selection = a 1.5px `scr.accent` orange border + the pink `ChipPip` on flat rows (F-09 — no sunken selection; pink stays the LED voice) · SUBMIT = `KeycapButton/destructive` (alert red — it files a moderation report) and sits dormant — flush, no travel — until a reason needing specifics has its note (MOD-01; the note is moderator-facing only, never shown to users) · the note rides `TextField/area`, debuting here: the cream inset (F-09's named text-input exception), ~3 rows, 11px navy ink · CANCEL stays cream/dim and a scrim tap (or ✕) backs out — destructive-adjacent actions always confirm (§1.8). BLOCK is never a reason and never the commit: an outlined alert strip past an OR divider — instant, silent, files nothing (SOC-09).

A1 — ReportSheet/drawer · catalog entry (required note empty → SUBMIT dormant)

The OptionSheet family grown into the report job: the ⋮ keycap (pressed beneath the scrim — keycaps keep F-09's pressed exemption) summons the drawer from the screen bottom over a dim scrim — no grab handle: summoned, not pulled. Reasons are flat hairline rows; INCORRECT INFO wears the selection — a 1.5px `scr.accent` orange border + the pink `ChipPip` over a ≤8% tint (F-09: never an inset, never a darkening) — and `TextField/area` discloses INLINE, directly beneath the selected reason: the cream inset (the named F-09 exception), ~3 rows, caret blinking on the placeholder.

The MOD-01 rule, visible: incorrect-info needs specifics, so with the note empty the red `KeycapButton/destructive` SUBMIT sits dormant — flush, no drop edge, no travel (a key with no travel can't be pressed); the hint line says why. CANCEL (cream) or a scrim tap backs out — destructive-adjacent actions always confirm (§1.8). The note is moderator-facing only — never rendered to other users.

A2 — ReportSheet/drawer · user (note written → armed · BLOCK is not a reason)

The same drawer worn by a user target (a friend profile's overflow, Friends tab active).
