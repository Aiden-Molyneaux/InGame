ReportSheet — converged states board · `/drawer` (Variation A) · 3 targets × the full state matrix

`ReportSheet` is the app-wide report pop-up for everywhere reports happen — published cards, catalog entries, and users (MOD-01). Variation A (`/drawer`) was ruled in report-sheet-drafts.html and normalized inside Add Game P3b; this board lifts that one instance into a dedicated state matrix faithful to P3b + design-spec §1.5 (B `/modal` and C `/takeover` stay in the drafts file as losing history — not carried here). One grammar on every target: flat hairline reason rows, selection = a 1.5px `scr.accent` orange border + the pink `ChipPip` (F-09, no sunken containers) · the required details note rides `TextField/area` (the cream inset, moderator-facing only — outside MOD-07's screening scope) · SUBMIT = red `KeycapButton/destructive`, dormant until a reason needing specifics has its note (MOD-01) · CANCEL cream · and on user targets only, BLOCK past an OR divider — instant, silent, files nothing (SOC-09). Reporting is a write, so it gates calmly offline (SYS-10).

State matrix — targets × states (this board)

Targets: published card (A1, B2) · catalog entry incl. report-duplicate (A2, A3, B1, B3, D1) · user + Block alongside (C1, C2). All three drawn.

States: entry/launch from the ⋮ overflow ✓ · reason picker ✓ · reason that requires the details note (MOD-01) ✓ · validation / dormant SUBMIT (no reason · or details required-but-empty) ✓ · submitting / in-flight ✓ · submitted / confirmation ("we'll review" — MOD-02 soft-hide, no thresholds) ✓ · Block + post-block confirmation (SOC-09) ✓ · offline / writes-gated (SYS-10) ✓ · submit error → Toast + RETRY (§1.8) ✓.

A2 — catalog entry · required details (MOD-01 · note empty → dormant)

The MOD-01 required-details rule, visible: on a catalog entry, INCORRECT INFO is selected (1.5px orange border + pink pip, F-09) — and because it needs specifics, the `TextField/area` discloses inline directly beneath the selected reason: WHAT'S INCORRECT? — REQUIRED FOR THIS REASON (the one required-marker voice). The cream inset is the named F-09 text-input exception; the caret blinks on its placeholder.

Validation state: the note is empty, so the red SUBMIT stays dormant and the hint says why it'll unlock. The note is moderators only — never rendered to other users, so it sits outside MOD-07's screening scope.

A3 — catalog entry · report duplicate (no note needed → SUBMIT armed)

The "report duplicate" reason (MOD-01). A second Elden Ring entry (ADDED BY KESTREL, in only 11 collections) is flagged as a DUPLICATE — ALREADY IN THE CATALOG. Duplicate is self-evident, so unlike INCORRECT INFO it needs no details note: the field stays tucked and the red SUBMIT is armed — full keycap edge, ready to travel. This is the MOD-01 asymmetry made visible against A2: same grammar, different required-details rule per reason.

The drawer reads cleaner with no disclosed field — the hint names what filing does (moderators merge the duplicate into the original entry, the api-contract's "duplicate" path).

B3 — submit failed (transient → Toast + RETRY, §1.8)

The write failed (network/timeout/5xx). The transient-failure surface is the converged `Toast` — the full-bleed banner sliding under the header (B's form, reused verbatim from the Store): COULDN'T FILE YOUR REPORT · NOTHING WAS LOST — YOUR NOTE IS STILL HERE, with the orange RETRY (`KeycapButton/action-alt`, safe to repeat).

The drawer stays put with the reason + note intact and SUBMIT re-armed — retry from the Toast or the keycap. This is an error, not offline (offline is the calm OfflineStrip in D1, never this alarm).

C1 — user · report + Block (SOC-09 handoff · armed)

The same drawer worn by a user target (a friend profile's overflow). One flow, two exits, zero ambiguity.

C2 — blocked (post-block confirmation · SOC-09)

The block confirmation. Tapping BLOCK swaps the sheet to a confirmation in the same grammar as B2 — but the seal wears the red ⊘ block glyph, the one note of alert: YOU BLOCKED RIKO. D1 — offline (the writes-gate — calm, SYS-10)

Reporting is a WRITE (SYS-10), so offline the sheet gates instead of pretending: the same lightweight `OfflineStrip` as Collection / Profile / Add Game rides under the header (one offline language app-wide), and the reason + note you've already entered are kept — the red commit relabels SUBMIT WHEN ONLINE and sits gated.

Never an alarm (offline ≠ error): no red, no SIGNAL LOST, no RETRY — the hint promises the report sends the moment you're back and it reconnects on its own. CANCEL stays live; the B3 Toast is the only red surface, reserved for a true failure.
