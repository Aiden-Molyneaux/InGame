Feedback & bug reporting (SYS-11) — Draft B “Dedicated sheet”

One of three distinct interaction models for the SYS-11 feedback surface. Draft B's answer to "how do you get from the Settings row to a filed report": you go somewhere — tapping the row opens a focused `FlowTakeover` that does one job, with room to do it well.

Thesis — a focused surface that earns the trip

The FEEDBACK row opens a dedicated SEND FEEDBACK takeover (`FlowHeader` ◂; the frame + NavBand persist). One roomy screen holds everything: a `SelectField` type picker (→ an OptionSheet), a tall `TextField/area`, and — for bugs — the `LogAttach` control in its fullest form. The big red SUBMIT closes it; a calm confirmation closes the loop.

MUST PROVE: the richer form earns the navigation — the trip buys clarity the inline row can't. B2 is the payoff: the bug path's extra affordances (toggle + a 2-line consent + a reserved OQ-060 payload panel with explicit room for size/preview) read effortlessly with space to breathe.

B1 — idle (the dedicated takeover · SUBMIT dormant)

A focused surface. The row opens a `FlowTakeover` — `FlowHeader` ◂ SEND FEEDBACK, the frame + NavBand persisting (PROFILE pressed). An intro line sets the support-facing frame ("never shown to other players"); then a `SelectField` type picker (FEEDBACK, with a one-line gloss) and a tall `TextField/area`. The red SEND FEEDBACK sits dormant until there's a message.

The whole screen does one job — the opposite of Draft A's quick inline row. The bet: that focus pays off most on the bug path (B2).

B1b — the type picker (`SelectField` → OptionSheet)

The type picker is the app's one drawer grammar. Tapping the `SelectField` raises an OptionSheet over a dim scrim — FEEDBACK (selected: orange border + pink pip, F-09) · SUGGESTION · BUG ("Something's broken — you can attach logs"). Each option carries a one-line gloss so the choice is legible at a glance.

This is Draft B's distinguishing type control — A uses inline segment keycaps; C makes the type the first whole screen. Here it's a conventional labeled field, the "stay legible in forms" half of the art direction.

B2 — bug + logs attached (the proof · the roomy `LogAttach`)

The navigation pays off here. With type = BUG, the message relabels WHAT WENT WRONG? and the full `LogAttach` `Well` appears: ATTACH INGAME LOGS + "OPTIONAL · HELPS US REPRODUCE IT" + the square `Toggle` ON; a two-line consent stating logs can hold personal info, go to support only, never shown to others, off by default; and the reserved OQ-060 payload panel — a doc tile + "INGAME DIAGNOSTIC LOGS / bundled when you send" + ATTACHED, with a dashed sub-row that explicitly reserves room for the bundle size + a summary once the format is defined, plus WHAT'S INCLUDED?.

Everything reads at once, nothing squeezed — the case for the trip. SEND BUG REPORT is the red `/destructive` commit.

B4 — submitted (`FeedbackConfirm` · full screen + DONE)

The takeover earns a clean close. The whole surface swaps to a centered `FeedbackConfirm` — the `scr.accent` check seal (support-facing "done"), THANKS — WE GOT IT, the plain-words "we read every one." A single DONE keycap returns to Settings (the ◂ FlowHeader does too).

Where Draft A confirms in a collapsing row, B gets a full beat — the trade-off of the dedicated surface: more ceremony, more closure.

B5 — send failed (transient → `Toast` + RETRY, §1.8)

The same §1.8 transient surface. A failed write drops the `Toast` under the FlowHeader — COULDN'T SEND YOUR REPORT · NOTHING WAS LOST — YOUR MESSAGE & LOGS ARE STILL HERE + orange RETRY. The whole form (type, message, logs toggle) stays intact; SEND re-arms. Offline would instead gate SEND calmly (SYS-10, no red) — this red is reserved for a true failure.
